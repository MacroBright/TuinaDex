# Ubuntu 实时双目点云查看器设计

## 目标

在 Ubuntu 笔记本本地桌面上运行一个原生单窗口应用，同时显示：

- 左相机实时彩色画面；
- 实时深度伪彩色图；
- 可旋转、缩放、平移的实时彩色三维点云。

程序直接读取 Ubuntu 的两台 V4L2 相机，不经 SSH 传输图像。平衡模式目标为约 5 FPS，优先保证界面可交互和深度尺度正确。

## 用户接口

新增命令：

```bash
python -m tools.stereo_calibration.realtime_viewer \
  --config ~/.config/tuinadex/stereo-upright-dry-run.json \
  --calibration /path/to/stereo_calibration.npz
```

单窗口布局：

- 左上：左相机彩色画面；
- 左下：深度伪彩色图，无效深度为黑色；
- 右侧：PyQtGraph OpenGL 三维场景，鼠标可旋转、缩放和平移；
- 顶部状态栏：实际 FPS、有效点数、中位深度和错误状态；
- 控件：暂停/继续、重置三维视角、退出。

第一版不录制视频、不保存每帧 PLY，不提供远程 WebGL，避免额外磁盘和网络开销。

## 架构与数据流

1. `OpenCVCameraPair` 在唯一后台工作线程中打开两台相机并同步抓帧。
2. 使用最新 `stereo_calibration.npz` 的映射表对左右画面去畸变和双目校正。
3. 平衡模式将校正画面缩小到 50% 计算 SGBM 视差，搜索范围按同一比例从 `-256…-1 px` 缩放为 `-128…-1 px`。
4. 视差图放大回标定分辨率并乘以 2，再用原始 Q 矩阵反投影，保持毫米深度尺度。
5. 过滤非有限点、无效视差及 `200…5000 mm` 之外的点，再空间降采样以控制每帧点数。
6. 工作线程只发布最新一帧不可变快照；Qt GUI 主线程通过定时器取最新快照并更新两张图像和点云。旧帧可被丢弃，不建立无限队列。

## 性能与参数

- 默认平衡模式：50% 视差分辨率，原始色彩，点云步长 4。
- 默认深度范围：`200…5000 mm`。
- 默认全分辨率视差范围：`-256…-1 px`。
- 界面以“最新帧”为准；若处理速度低于相机帧率，丢弃中间帧而不累积延迟。
- 初始点云视角自动对准有效点的轴对齐包围盒。

## 错误和生命周期

- 配置、标定文件、映射表尺寸或 Q 矩阵无效时，在打开相机前拒绝启动。
- 相机打开、抓帧或处理失败时，界面显示错误并停止发布新帧，不重复显示旧帧伪装实时数据。
- 关闭窗口或点击退出时，通知工作线程停止、释放两个 V4L2 句柄，再结束 GUI。
- 点云暂时少于 1000 点时不退出，显示“有效点不足”并等待后续帧。

## 依赖与部署

- 复用现有 `tuinadex_hw` Conda 环境中的 OpenCV、NumPy 和相机配置。
- 新增 PyQt5、PyQtGraph 和 PyOpenGL 用于 Ubuntu 本地 GUI。Open3D 0.19 在当前 Ubuntu Wayland/XWayland 会话中最小窗口也会段错误，因此不用于正式界面。
- 程序必须在 Ubuntu 桌面会话中运行，需有可用的 `DISPLAY`/Wayland-XWayland；纯 SSH 无显示会话时给出明确错误。

## 验证范围

按用户要求保持精简：

- 聚焦测试视差缩放后的深度尺度、无效点过滤和“最新帧”快照语义；
- 使用伪造相机完成一次工作线程启停测试；
- 在 Ubuntu 桌面上进行一次真实相机冒烟验证，确认单窗口可更新、点云可交互、退出后相机已释放。

## 不在范围内

- 点云模型分割、背部穴位识别和机器人控制；
- 点云帧录制、回放和视频编码；
- 网页远程流媒体或 SSH 图像传输；
- GPU/CUDA 视差算法。
